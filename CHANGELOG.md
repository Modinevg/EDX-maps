# Журнал изменений — EDX processing

Проект правится с нескольких компьютеров через OneDrive. Код с 2026-11-09 в git и на GitHub
(https://github.com/Modinevg/EDX-maps), но каждое изменение по-прежнему записывается сюда: дата, затронутые
файлы, что сделано и зачем, как проверено. Новые записи — сверху.

Файлы: `edx_core.py` — вычисления (без GUI), `edx_gui.py` — интерфейс (PyQt5 + pyqtgraph),
`edx_xray_lines.py` / `build_xray_lines.py` — таблица рентгеновских линий, `run_edx_gui.bat` — запуск,
`setup_edx_env.bat` + `requirements.txt` — установка Python и библиотек на новом компьютере.

## 2026-11-09 — установка окружения на новом компьютере (`setup_edx_env.bat`)

**Зачем:** чтобы запустить программу на другой машине без ручной установки Python и пакетов.

**`setup_edx_env.bat`** (запустить один раз двойным щелчком):
- Скачивает Python 3.12.10 — официальная сборка python.org в виде пакета nuget.org (14 МБ, с pip). Пакет
  распаковывается в `%LOCALAPPDATA%\EDX_processing\python`.
  - Права администратора не нужны, записей в реестре нет, PATH и другие Python не меняются.
  - Удаление — удалить эту папку. Другое место — переменная `EDX_ENV`.
  - Папка не в OneDrive: ~500 МБ библиотек не синхронизируются, Python у каждой машины свой.
- Ставит библиотеки из `requirements.txt` (~150 МБ скачивания) и проверяет импорт `edx_core` и `edx_gui`.
- Окружение изолировано: `PYTHONNOUSERSITE=1`, `PYTHONPATH` и `PYTHONHOME` очищаются, поэтому пакеты из
  `pip install --user` и переменные Anaconda не подмешиваются.
- Повторный запуск приводит библиотеки к версиям `requirements.txt`. Если Python неполный, он скачивается
  заново. Признак неполного Python: нет `Lib\os.py`, ориентира стандартной библиотеки (сам `os` встроен в
  интерпретатор, поэтому одного импорта мало), или не импортируется pip.
- Распаковка с `tar -m`, чтобы файлы получили текущую дату. Иначе у них даты архива (апрель 2025), и
  программы очистки старых файлов их удаляют. При проверке в %TEMP% так пропала половина стандартной
  библиотеки.
- Нужны `curl.exe` и `tar.exe` (есть в Windows 10 1803 и новее) и доступ к nuget.org и pypi.org.

**`requirements.txt`:** все версии зафиксированы (с зависимостями), чтобы на всех машинах был проверенный
набор:
- версии этого компьютера: numpy 1.26.2, scipy 1.11.4, PyQt5 5.15.11, pyqtgraph 0.14.0, matplotlib 3.8.2,
  Pillow 10.1.0, tifffile 2023.12.9, python-pptx 1.0.2;
- зависимости — те, что pip поставил при проверке.

**`run_edx_gui.bat`:** запускает Python из `%LOCALAPPDATA%\EDX_processing`, если он есть, иначе, как раньше,
`python` из PATH.

**Проверка:**
- Установка с нуля в отдельную папку — 50 с.
- Повторный запуск на сломанном Python (удалена часть стандартной библиотеки) — Python поставлен заново.
- В новом окружении всё совпадает с рабочим окружением этого компьютера:
  - GUI-тест 01592: те же 11 элементов, χ²/ν 19.87;
  - автоопределение на 6 наборах;
  - презентация (без кириллицы);
  - наложение SEM-изображения, горячие пиксели, ручной выбор компонент PCA;
  - предобработка, биннинг и локальный PCA.
- `run_edx_gui.bat` открывает окно программы из нового окружения. Без него — из `python` в PATH.

## 2026-11-07 — локальный PCA по плиткам (дополняет глобальную модель)

**Идея из MSA** («Spatial Local wPCA», HREM Research): карта режется на плитки с перекрытием в полплитки, и
каждая раскладывается отдельно. Фаза, занимающая часть карты, в своей плитке выходит над шумом раньше, чем во
всей карте.

**Отличие от MSA.** В MSA каждая плитка восстанавливается только по своим компонентам (одно k на все). Мы
проверили такую схему (плитки 128 px): на 01593top она сохранила лишь 81 %, 64 % и 32 % амплитуды трёх слабых
протяжённых глобальных компонент — в отдельной плитке им не хватает пикселей. Поэтому сделано так:
**модель плитки = выбранная глобальная модель + те сигнальные компоненты плитки, которые больше чем
наполовину лежат вне неё**. Локальный PCA только добавляет; без добавок результат равен глобальному
восстановлению.

**`edx_core.py`:**
- `local_pca_decompose(si, erange, tile, poisson, binning, skip_noise, progress)` → `LocalPCA`.
  - Плитки — `_tile_starts`, последняя прижата к краю. Каждая плитка — `pca_decompose` с 24 компонентами.
  - У `LocalPCA` есть `model(p)` — сигнальные компоненты плитки — и `tile_map(values)`.
- `_local_basis(pca, comps, p, model)`. Компоненты плитки переводятся в весовое пространство глобального PCA;
  к глобальному базису добавляются сингулярные векторы их части вне глобальной модели с сингулярным числом
  > `LOCAL_PCA_NEW = 0.5`.
- `local_pca_added(lp, pca, comps)` — число добавленных направлений по плиткам.
- `local_pca_reconstruct(si, lp, pca, comps)` — проекция спектров плитки на её базис. Плитки сшиваются весами
  sin² (`_tile_weights`: при сдвиге на полплитки сумма весов постоянна, швов нет).
- `_top_eigh`: при малом числе нужных собственных значений (24 из ~2000) — метод Ланцоша (`eigsh`). Он в
  ~4 раза быстрее, значения те же (1e-15). Глобальный PCA (150 значений) считается, как раньше, LAPACK.

**`edx_gui.py`:**
- На вкладке PCA добавлена галочка «локальный PCA, плитки [64] px», применяется кнопкой «Вычислить PCA».
  Графики и карты компонент — глобальное разложение; k и «Состав» задают глобальную часть модели.
- «Использовать восстановленные данные» → глобальная модель + локальные добавки. Состояние учитывает k,
  состав и «без шумовых».
- В подписи — плитки, число сигнальных компонент в плитке и где добавлены направления. Изображение
  «Локальный PCA: добавлено» на вкладке «Спектр» показывает число добавленных направлений по карте.
- В строке состояния, в презентации и в экспорте карт: «5 комп. + локальный PCA (плитки 64 px, добавлено в 3
  из 18)».
- `pca.npz`: `local_tile`, `local_tiles`, `local_signal_components`, `local_added`, `local_added_map`.
- Справка: абзац о локальном PCA.

**Проверка:**
- Пятно Zr K 16×16 пикселей, добавленное в EDXmap1, плитки 64 px. Доля Zr, оставшаяся в пятне:

  | Zr, отсч./пикс. | глобальный PCA | только плитки (как MSA) | гибрид |
  |---|---|---|---|
  | 1 | 3 % | 9 % | 3 % (сигнал ниже шума и в плитке) |
  | 2 | 3 % | 37 % | **56 %** |
  | 4 | 79 % | 88 % | 85 % (Zr уже в глобальной модели) |

- Без добавок гибрид совпадает с глобальным восстановлением (3e-7). Одна плитка размером с карту даёт
  глобальный результат (6e-8).
- Швов на картах Cu K и суммы отсчётов нет; сумма отсчётов сохраняется.
- Чистые карты: на Cement ничего не добавлено. На EDXmap1 — 2 плитки в левом верхнем углу: вариация Al/O
  (3 направления) и одно направление, похожее на шум.
- Время на EDXmap1 200×125: 17 с на разложение (18 плиток) и 5 с на восстановление. На карте EDAX 400×512:
  48 с (плитки 128 px, 42 плитки) или 88 с (64 px, 180 плиток) плюс 16 с.
- GUI без окна: разложение, подпись, изображение «добавлено», восстановление совпадает с ядром,
  «без шумовых», карты, экспорт, презентация, возврат к глобальному, сброс. Прежние тесты PCA и биннинга,
  прямой запуск — проходят.

## 2026-11-07 — PCA: биннинг для разложения (как в MSA, HREM Research)

**Повод:** сравнение с плагином MSA для DigitalMicrograph (папка `MSA`: плагин 2.3.1 и руководства 2.3 и 3.0).
- MSA делает тот же взвешенный PCA с нормировкой Spectral-Spatial (Keenan & Kotula). Число компонент там
  выбирается на глаз, есть остаток восстановления и локальный PCA.
- MSA предлагает «Spatial binning» перед разложением, «не ухудшающий разрешение результата».
- Код MSA не изучить: основная библиотека `DMMSA64.dll` зашифрована защитой Sentinel HASP (секции `.AKS1`/`.AKS2`,
  энтропия 8 бит/байт) под USB-ключ. Снимать защиту не стали. Читаются только импорты Intel MKL; в
  `DMMSAUtils64.dll` — биннинг и ввод-вывод.

**`edx_core.py`:**
- `bin_pixels(data, b, sel)` — суммирование по блокам b×b. Неполные блоки у правого и нижнего края в
  разложение не входят. Считается по частям, только по выбранным каналам.
- `pca_decompose(..., binning=1)`. При b > 1 по сбинированным данным находятся:
  - собственные значения, спектры компонент (нагрузки);
  - веса пикселей и каналов (суммы каналов — по тем же пикселям);
  - граница шума Марченко–Пастур (по числу блоков), r и классификация сигнал/шум.

  Счета — проекции спектров исходных пикселей на нагрузки, в полном разрешении. Веса пикселей в картах счетов
  и в восстановлении сокращаются. Карты, у которых по стороне меньше 2 блоков, не бинируются.
- `PCAResult.binning`.

**`edx_gui.py`:**
- На вкладке PCA добавлен выбор «Биннинг для разложения: нет / 2×2 / 4×4» (по умолчанию «нет» — как
  раньше), применяется кнопкой «Вычислить PCA».
- В подписи над графиками указаны блоки разложения; r помечено как «по блокам разложения».
- `binning` записывается в `pca.npz` при экспорте PCA.
- Справка: абзац о биннинге.

**Проверка** (4 карты TIA и EDAX):
- Без биннинга результат тот же, что до правки: те же собственные значения и сигнальные компоненты.
- Встроенный биннинг точно совпадает с разложением заранее сбинированных данных: собственные значения,
  нагрузки и классификация.
- Сумма карт счетов полного разрешения по блоку равна карте сбинированного разложения (до 1.5·10⁻⁶).
- Восстановление сохраняет сумму отсчётов.
- Сигнальных компонент (без / 2×2 / 4×4):
  - EDXmap1 — 5 / 5 / 5;
  - Cement_x4__0005 — 5 / 7 / 6;
  - SEM-карта EDAX — 4 / 4 / 6;
  - 01593top — 3 / 4 / 5.
- В 01593top при 4×4 появляются две явные фазы (полосы Na, O, Ti; r = 0.91 и 0.68), которые без биннинга
  были чуть выше границы шума (1.6) и считались шумом.
- Пограничные новые компоненты (λ/граница 1.1–1.4) — слабые вариации состава (например, Mn/Fe) с примесью
  артефактов развёртки (полоса в первых строках, горячие пиксели в начале строк). Их стоит оценивать по
  карте.
- Время почти не меняется (EDAX: 8.5 с без биннинга, 8.9 с при 2×2, 5.7 с при 4×4): основное время занимает
  проекция всех пикселей.
- GUI без окна: разложение 2×2 (EDXmap1) и 4×4 (01593top), карты полного размера, восстановление, карты MLLS,
  экспорт. Прежний тест цепочки PCA и прямой запуск проходят.

## 2026-11-07 — проверка карт: зависит ли распределение элемента от модели фона

**Повод:** на EDXmap1 с PCA Fe появлялся в частицах Pd и в полосе Ag. Разбор показал, что PCA его не создаёт.
- Карта с PCA — это проекция исходной карты на карты компонент.
- Попиксельный MLLS и без PCA даёт в частицах 0.048 ± 0.007 отсчёта Fe на пиксель (в Pt — 0.010 ± 0.003), но
  в отдельных пикселях это скрыто шумом.
- В суммарном спектре частиц пика Fe Kα нет: 49 ± 35 отсчётов из 230 тыс.
- При другой модели фона Fe по фазам меняется на сотни отсчётов при погрешности ±50: в полосе Ag от 8 до
  504, в Pt от −36 до 376.

Вывод: под слабой линией фон данными не определён, его ошибка в несколько процентов уходит в элемент и
распределяется как главные фазы. PCA и бининг убирают шум и делают её видимой.

**`edx_core.py`:**
- `map_filter` — линейный МНК попиксельного фита вынесен из `compute_maps` (результат прежний, расхождение
  ~1e-14). Веса записаны без множителя n_pix, решение от этого не меняется.
- `phase_spectra` — суммарные спектры фаз считаются по частям, без копии куба. Используется в
  `phase_backgrounds` (новый аргумент `spectra`).
- `map_background_check` и `MapCheck`. Суммарный спектр каждой фазы фитуется тем же фильтром, что и карты, с
  несколькими моделями фона. Распределение по фазам при другой модели сравнивается с распределением карт с
  точностью до масштаба и сдвига, потому что показ карты растягивает её диапазон, а привязанные серии меняют
  только отношение. В расчёт идёт остаток аффинной подгонки сверх 3σ разности, отнесённый к контрасту между
  фазами. Если ни одна фаза не изменилась сверх 3σ, изменения нет. Погрешности — из отсчётов × дисперсия.
- `map_structure` — пространственная структура карты: ковариация соседних пикселей в σ белого шума.
- Константы `MAP_BG_SHARE = 0.5`, `MAP_PHASE_SIGMA = 3`, `MAP_STRUCTURE = 5`.

**`edx_gui.py`:**
- Проверка выполняется при каждом расчёте карт MLLS (`_check_maps`), если в карте не меньше 100 пикселей.
  - Модели фона: модель карт, тот же фон × полином на 2 и на 4 порядка выше, для SNIP — окно в 1.5 раза
    шире.
  - Фазы — те же, что у фона по фазам.
  - При картах с PCA проверяются данные до PCA (после предобработки): фон под линией — свойство измеренных
    спектров, а вердикт не должен зависеть от галочки PCA.
- **⚠ фон** — контраст между фазами меняется больше чем на 50 % (или обращается).
- **⚠ шум** — различие между фазами меньше 3σ, и у карты (данных до PCA) нет пространственной структуры.
- Где видна пометка:
  - подпись карты в сетке;
  - «⚠» у элемента в таблице карт; во всплывающей подсказке — средние по фазам при каждой модели и ±1σ;
  - строка под композитом;
  - слайд композита и подписи карт в презентации;
  - `map_warnings` и `map_background_check` в `maps_raw.npz` при «Сохранить все карты».
- Помеченные карты по умолчанию не входят в композит: в него берутся 4 самые сильные из непомеченных. Выбор,
  сделанный вручную, не меняется.
- Подпись карты в сетке теперь в две строки (название и пометки / диапазон), колонки не уже 140 px.
- Справка: раздел «Проверка карт».

**Проверка** (без окна, 11 файлов TIA и EDAX):
- `map_filter` совпадает с прежней формулой (2e-14), карты — до 5e-7.
- Сильные линии не помечаются ни разу: доля у них 0–0.02.
- Помечаются только слабые линии, обычно < 0.1 отсчёта на пиксель:
  - EDXmap1 — Si, Fe, Na (фон);
  - 14.29.53 — Si, Se (фон; средние отрицательные), F, Mg, Al (шум);
  - SEM-карта EDAX — Pt M, S, Mg, Sc, Rh, Co (фон), Si, Ca (шум);
  - 09.32.20 — O, Ga, Ag, Mg (шум);
  - Cement_x4__0006 — K (шум);
  - 01592 — Mg (шум); 01593 — Mg (фон), Ca (шум).
- На EDXmap1 вердикт одинаков с PCA и без. Проверка добавляет 0.2–0.5 с к расчёту карт.
- Прежний тест цепочки PCA и прямой запуск проходят.

## 2026-11-07 — PCA по схеме «исходный куб → предобработка → разложение»

**Было:** перед SVD данные проходили только выбор диапазона энергий, отброс каналов без отсчётов и
пуассоновскую нормировку. Явной предобработки (мёртвые каналы, дрейф энергии, плохие пиксели) не было.

**`edx_core.py`** — новый раздел «Preprocessing for the PCA»:
- `preprocess(si, det, erange, channels, drift, pixels, pixel_sigma)` → (данные для PCA, отчёт `Preprocessing`).
  Данные копируются, только если что-то изменено; без коррекции дрейфа остаются целыми отсчётами.
- **Мёртвые каналы** — `find_dead_channels`: канал суммарного спектра, отличающийся от среднего двух соседних
  больше, чем допускает линия шириной FWHM детектора (A/s² + 8σ шума; край порога регистрации не проверяется).
  Худший канал заменяется, тест повторяется. В кубе такие каналы заменяются интерполяцией по соседним
  (`_replace_channels`, для целых данных — стохастическое округление). Каналы без отсчётов считаются в отчёте.
- **Дрейф энергии** — `energy_drift`: строки развёртки (время съёмки) делятся на 16 блоков. Сдвиг спектра
  блока относительно суммарного измеряется по ≤ 6 сильным пикам: линеаризованный МНК
  c·r − c·d·r′ + a + b·E, у каждого пика своя амплитуда, потому что состав блоков разный. Коррекция
  построчная (`_shift_channels`, линейная интерполяция) и применяется, только если p < 0.001, сдвиг больше
  0.2 канала и пики согласуются (χ²/ν < 4).
- **Плохие пиксели** — `find_bad_pixels`: сумма отсчётов пикселя против второго по яркости (темноте) из
  8 соседей, точный биномиальный тест равенства пуассоновских интенсивностей, порог 5σ. Линии, края и частицы
  от 2×2 пикселей не трогаются. Замена — спектром соседа с медианной суммой (`_replace_pixels`).
- Константы `PRE_*`. Импорт `scipy.signal.find_peaks`, `scipy.special.betainc / gammaincc / ndtri`.
- `pca_decompose` теперь получает предобработанные данные. Нагрузки (loadings) — `factors`, счета (scores) —
  `scores`; данные ≈ Σ `score_map(i)` × `spectrum(i)`.

**`edx_gui.py`** — вкладка PCA:
- Строка «Предобработка: ☑ мёртвые каналы ☑ дрейф энергии ☑ плохие пиксели [5.0 σ]», применяется кнопкой
  «Вычислить PCA». Отчёт показывается над графиками, сдвиги по блокам строк — во всплывающей подсказке.
- `run_pca`: `si_raw` → `core.preprocess` → `si_pre` → `pca_decompose`. «Использовать восстановленные данные»
  восстанавливает `si_pre`.
- «Изображение» → «Плохие пиксели» на вкладке «Спектр»: сумма отсчётов, заменённые пиксели обведены красным.
- «Экспорт PCA…» сохраняет `eigenvalues.csv`, `loadings.csv`, `scores.tif` (float32) и `pca.npz` (всё вместе
  с весами и отчётом предобработки) в папку `<имя>_pca`.
- Подписи: «Собственные значения (eigenvalues)», «нагрузка (loading)», «счета (scores)».
- Проверка карт «⚠ PCA» теперь сравнивает с картами данных до PCA, но после предобработки: так она оценивает
  только влияние PCA.
- В презентации на слайде композита при данных PCA добавлена строка «Preprocessing before PCA: …».
- Справка, раздел PCA: описание схемы и всех трёх шагов.
